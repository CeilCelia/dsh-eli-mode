# 记忆与技能管理规范

知识库分两层：**mem（记忆）** 和 **skill（技能）**。保持长期可维护性的关键：分清什么记到哪、怎么记。

## 什么写进 mem/

- 用户的明确偏好、纠正与长期指令（避免每次重复说明）
- 项目的关键决策、约束与背景（供后续会话衔接）
- 重要的事实与参考数据（避免凭印象）

## 什么写进 skill/

- 验证过的工作流程、SOP 与成功做法
- 格式固定：**触发条件 → 动作 → 验证**（什么时候用 / 怎么做 / 怎么确认做对）
- **只写成功的经验**：失败教训要反转成"怎么做对"再写

## 什么不该写入

- 一次性、临时性的过程信息（对话本身已记录）
- 敏感凭据（密钥放凭据服务或环境变量，绝不进 wiki）
- 过期且无保留价值的内容（应及时更新或删除）
- 跑分/测试中的**答案线索**：判分标准、期望输出、题目布局（会让评测作弊）

## 写入格式

- id 用小写路径：`mem/xxx`、`skill/xxx`
- 正文以 `# 标题` 开头，小节用小标题
- 条目间用 `[[id]]` 双链互关联，形成知识图谱
- 旧条目按需更新：合并新信息、删除过时内容

## 维护节奏

- 会话结束，值得留存的结论随手 `kb_write`
- 定期 `kb_list` + 网页端清理失效条目
- 目录页由系统自动生成，无需手工维护

# 记忆管理规范

智能体的记忆以知识库条目形式持久化。为保持长期可维护性，请遵循以下规范。

## 什么值得写入

- 用户明确的偏好、纠正与长期指令（避免每次重复说明）
- 项目的关键决策、约束与背景（供后续会话衔接）
- 验证过的工作流程、SOP 与踩坑记录（供复用）
- 重要的事实与参考数据（避免凭印象）

## 什么不该写入

- 一次性、临时性的过程信息（对话本身已记录）
- 敏感凭据（密钥应放在凭据服务或环境变量，绝不入 wiki）
- 过期且无保留价值的内容（应及时更新或删除）

## 写入格式

- id 用小写路径：`projects/foo`、`research/bar`、`workflows/xxx`
- 正文以 `# 标题` 开头，分节用小标题
- 条目间用 `[[id]]` 双链关联，形成知识图谱
- 旧条目按需更新：合并新信息、删除过时内容

## 维护节奏

- 会话结束时，值得留存的结论随手 `kb_write`
- 定期 `kb_list` + 网页端清理失效条目
- 目录页由系统自动生成，无需手工维护
